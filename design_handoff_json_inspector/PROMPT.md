Ты работаешь в репозитории json-inspector (Go + Wails v2 + Vue 3 + TypeScript). Нужно внедрить редизайн интерфейса.

Сначала прочитай три файла и не меняй ничего до конца чтения:

- `design_handoff_json_inspector/IMPLEMENTATION_PLAN.md` — пошаговый план (шаги 0–9) с файлами, критериями приёмки и деталями по каждому шагу.

Это дизайн-референс, а не код для копирования: бери из него состав элементов, порядок, плотность и значения, но реализуй в существующей среде проекта (Vue 3 SFC + Tailwind v4 через @apply + CSS-переменные из frontend/src/style.css).

Затем выполни шаги 1–8 плана последовательно, в указанном порядке. Шаг 9 (состояние перехвата из расширения, правки в Go и в extension/) выполняй последним и только если шаги 1–8 прошли сборку.

Правила на всю работу:
- Новых цветов не вводить. Только переменные из frontend/src/style.css. Тёмная тема обязана работать — она уже описана в @media (prefers-color-scheme: dark). Захардкоженных hex вне style.css быть не должно.
- Стили — как в проекте: `<style scoped>` + `@reference "../style.css"` + `@apply`; общие классы — в style.css.
- Иконки — только через Icon.vue (lucide, stroke-width 1.5). Нужна новая — добавь в карту ICONS, не рисуй SVG вручную.
- Переиспользуй существующие утилиты: statusClass, methodClass, formatBytes, formatDuration, decodeUrl, tryParseJson, highlightJson из lib/json.ts; shortcut() из lib/platform.ts; copyToClipboard, exportRequest из lib/export.ts; buildIndex, dataResources, resourceMatchesQuery из lib/jsonapi.ts.
- Ничего не ломай по дороге: после каждого шага приложение должно собираться и работать.
- Комментарии в коде — в стиле проекта: объясняют «почему», а не «что».

Процесс по каждому шагу:
1. Скажи одной строкой, какой шаг начинаешь.
2. Внеси изменения.
3. Запусти `make build` (или `cd frontend && npx vue-tsc --noEmit` для быстрой проверки типов, если полная сборка долгая).
4. Проверь себя по списку «Приёмка» этого шага и отчитайся по каждому пункту.
5. Сделай отдельный коммит: `redesign(step N): краткое описание`.
6. Переходи к следующему шагу без вопросов, если шаг прошёл приёмку.

Останавливайся и спрашивай меня только в трёх случаях: план расходится с кодом так, что решение неочевидно; шаг требует удалить функциональность, не упомянутую в плане; сборка падает и причина не в твоих правках.

Не делай ничего сверх плана: новых фич, рефакторинга несвязанных файлов, переименований, обновления зависимостей, изменения CI. Окружения и переменные, коллекции, диффы ответов — в этот заход не реализуются, под них в плане только зарезервировано место.
