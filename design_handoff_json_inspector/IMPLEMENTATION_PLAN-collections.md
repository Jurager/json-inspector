# План реализации: коллекции

Продолжение `IMPLEMENTATION_PLAN.md` (шаги 0–9) и `IMPLEMENTATION_PLAN-env-extension.md` (A1–A8, B1–B4, C1). Спецификация — `README-collections.md`, дизайн-референс — блок **06 · Коллекции** в `JSON Inspector - Зоны и редизайн.dc.html`. Каждый шаг самодостаточен: после него приложение собирается и работает.

Общие правила — те же, что в предыдущих планах: новых цветов не вводить, только `frontend/src/style.css`; тёмная тема обязана работать; иконки через `Icon.vue`; стили `<style scoped>` + `@reference` + `@apply`; комментарии объясняют «почему».

---

## Шаг D1 — стор и модель

**Файлы:** `frontend/src/stores/collections.ts` (новый).

1. Состояние и экшены по разделу «Состояние» спецификации. `addRequest`/`addFolder` принимают `parentId` (коллекция или папка).
2. Персист в `localStorage` под `ji-collections-v1`, тем же способом, что `ji-history-v1`.
3. `run(nodeId)`: собирает плоский список запросов поддерева в порядке обхода, выполняет по очереди через существующий HTTP-клиент приложения (`app.go`/Wails), пишет результат каждого в `lastRun`, не останавливается на ошибке.

**Приёмка:** дерево и правки переживают перезапуск; `run` на папке трогает только её запросы; ошибка одного запроса не прерывает остальные.

## Шаг D2 — дерево в зоне списка

**Файлы:** `frontend/src/components/CollectionTree.vue` (новый), `frontend/src/App.vue`.

1. Разметка по спецификации: шапка 40px с «+», строки трёх уровней с отступами 0/24/40px, метод `min-width: 40px` у запроса.
2. Разворот/сворачивание с сохранением состояния в `expanded` (Set в сторе).
3. Выделение строки — `selectNode`, обновляет содержимое зоны контента (шаг D3/D5).
4. Фильтр внизу — тот же докнутый паттерн, что в `HistoryPanel`; фильтрует по имени, разворачивает путь до совпадения.
5. В `App.vue`: для `activeView === 'collections'` рендерить `CollectionTree` в зоне списка вместо `HistoryPanel`.
6. Пустое состояние: при `collections.length === 0` не рендерить `CollectionTree` вообще — зона контента (`CollectionsEmptyState.vue`, новый) занимает всё пространство после рейла: заголовок, пояснение, «+ Новая коллекция», «Импортировать коллекцию». Статус-бар остаётся на всю ширину окна как обычно.

**Приёмка:** разворот/выбор не дёргает layout; фильтр на «категор» разворачивает и подсвечивает «Список категорий» и «Дерево категорий»; DELETE и OPTIONS не обрезаются в строке запроса; без коллекций панель списка не рисуется, и её появление после создания первой коллекции сразу выбирает её.

## Шаг D3 — карточка запроса без перехода

**Файлы:** `frontend/src/components/RequestBuilder.vue`, `frontend/src/components/ResponseViewer.vue`, `frontend/src/App.vue`.

1. `RequestBuilder` и `ResponseViewer` принимают источник данных как проп (`store.draft` для режима «Запрос», элемент коллекции для режима «Коллекции») — не дублировать компоненты. Титлбар не меняется.
2. `StatusBar` для источника «Коллекции» рендерит слева хлебные крошки `Коллекция › Папка › Имя`, справа — индикатор несохранённой правки + «Сохранить» (видны только при `dirty`) и сводку документа. Ничего в зоне 4/5 не резервирует под это высоту.
3. Правка любого поля помечает элемент в `dirty` (сторе `collections`); «Сохранить» пишет `dirty` обратно в `collections.items` и очищает флаг; «Отправить» выполняет запрос как обычно, не трогает `dirty`.
4. Рейл не переключается: `App.vue` продолжает рендерить `CollectionTree` в списке при открытой карточке.

**Приёмка:** открытие запроса из дерева не меняет `activeView`; правка URL показывает индикатор и кнопку «Сохранить»; «Отправить» без «Сохранить» не меняет сохранённые данные; повторное открытие показывает последнее сохранённое состояние.

## Шаг D3б — создание в дереве и предупреждение о несохранённом

**Файлы:** `frontend/src/components/CollectionTree.vue`, `frontend/src/stores/collections.ts`, `frontend/src/App.vue`.

1. «+» в шапке списка создаёт коллекцию сразу в режиме ввода (тот же паттерн, что у `EnvironmentsSheet` — имя выделено, Enter сохраняет, Esc отменяет, пустое имя/дубликат блокируют сохранение, инпут 26px в ритме строки 30px).
2. «Новый запрос» создаёт строку с методом (чип, по умолчанию GET, кликабелен) и именем в режиме ввода на том же уровне.
3. Системный `confirm`-алерт (через Wails `runtime.MessageDialog` с тремя кнопками, либо кастомный оверлей той же геометрии) при попытке сменить `selectedId`/`activeView`/закрыть окно, пока `dirty` не пусто: «Не сохранять» / «Отмена» / «Сохранить». Перехватывать переход до его завершения — отмена остаётся на месте.

**Приёмка:** новая коллекция и новый запрос создаются без диалога, за один жест; переход с несохранённой правки на другой узел, на «Запрос»/«Браузер» или закрытие окна всегда спрашивает; «Отмена» не теряет ни правку, ни выделение.

## Шаг D4 — контекстное меню и операции

**Файлы:** `frontend/src/components/CollectionTree.vue`, `frontend/src/components/Icon.vue`.

1. Правый клик — тот же `.menu`, что в остальном приложении: позиционирование под курсором, закрытие по Esc/клику вне/повторному правому клику (`onDocClick`).
2. Пункты: «Переименовать» (инлайн-редактирование строки, паттерн Finder — как у окружений), «Дублировать», «Экспорт запроса», разделитель, «Удалить» (подтверждение, если внутри больше одного запроса). На коллекции/папке — «Новая папка», «Новый запрос» в начале списка.
3. Новые иконки в `ICONS`: `Copy`, `Trash` (`Bookmark`, `Play`, `Download`, `Upload` — см. шаги D5/D6).

**Приёмка:** переименование не сдвигает высоту строки; дублирование создаёт копию с суффиксом «(копия)» на том же уровне; удаление папки с 5 запросами спрашивает подтверждение, удаление пустой папки — нет.

## Шаг D5 — сохранение из командной строки

**Файлы:** `frontend/src/components/RequestBuilder.vue`, `frontend/src/components/SaveToCollectionSheet.vue` (новый).

1. Кнопка-закладка 32×32 в командной строке режима «Запрос», рядом с «Отправить». Иконка `Bookmark` в `ICONS`.
2. `SaveToCollectionSheet`: поповер 320px, поле имени (предзаполнено путём без query), список коллекций/папок для выбора места, «Отмена»/«Сохранить».
3. «Сохранить» вызывает `collections.addRequest(parentId, snapshot)`, где `snapshot` — метод/URL/параметры/заголовки/auth/тело текущего черновика; `store.draft` не меняется.

**Приёмка:** сохранённый запрос сразу виден в дереве коллекций на выбранном уровне; черновик в командной строке остаётся как был; поповер закрывается по Esc и клику вне.

## Шаг D6 — обзор коллекции и прогон

**Файлы:** `frontend/src/components/CollectionOverview.vue` (новый), `frontend/src/components/StatusBar.vue`.

1. Разметка по спецификации: шапка с именем/описанием, ряд действий, сводка из 4 блоков, построчные результаты.
2. «Запустить коллекцию» вызывает `collections.run(nodeId)`; на время выполнения кнопка — «Остановить» (устанавливает флаг отмены, дочитывает текущий запрос до конца).
3. Пока `store.running`, `StatusBar` показывает «Прогон: N/M · имя коллекции» слева (тот же слот, что у состояния окружения/расширения — они не показываются одновременно, потому что относятся к разным `activeView`).
4. `App.vue`: для `activeView === 'collections'` и выбранного узла — коллекция/папка (`selectedId` не лист) — рендерить `CollectionOverview` в зоне контента вместо карточки запроса.

**Приёмка:** прогон 8 запросов проходит все, несмотря на 2 ошибки; сводка совпадает с построчными результатами; статус-бар отражает прогресс и возвращается к обычному состоянию по завершении.

## Шаг D7 — импорт/экспорт

**Файлы:** `frontend/src/lib/postman.ts` (новый), `frontend/src/components/CollectionOverview.vue`, `frontend/src/components/CollectionTree.vue`.

1. `parsePostmanCollection(json)` → `Collection`; `toPostmanCollection(collection | request)` → JSON по схеме v2.1.
2. «Импорт» — диалог выбора файла (Wails), парсинг, добавление как новая коллекция; невалидный формат — сообщение об ошибке, ничего не создаётся.
3. «Экспорт» на коллекции — сохранение файла через диалог; «Экспорт запроса» в контекстном меню — файл с одним `item`.
4. Секреты не сериализуются — переменные окружения остаются токенами `{{name}}` (используется `lib/vars.ts` из пакета 2, без подстановки значений).

**Приёмка:** экспортированная и повторно импортированная коллекция даёт идентичное дерево; импорт реальной Postman-коллекции (без вложенных `item` глубже 2 уровней) не падает; экспорт не содержит значений секретов.

## Что проверить в конце

- Открытие сохранённого запроса не переключает рейл и не создаёт черновик в режиме «Запрос».
- Прогон не останавливается на первой ошибке и не блокирует интерфейс.
- Контекстное меню работает на всех трёх уровнях дерева с уместным набором пунктов.
- Фильтр, сохранение из командной строки и импорт/экспорт не требуют переключения экрана.
- Тёмная тема: ни одного захардкоженного цвета вне `style.css`.
