# JSON Inspector — дизайн-система

Справочник для разработки. Визуальная спецификация с примерами — в блоке **08 · Справочник** файла `JSON Inspector - Зоны и редизайн.dc.html`. Здесь — то же самое в виде значений для кода.

## Шрифты

- UI: `-apple-system, BlinkMacSystemFont, 'SF Pro Text', 'Helvetica Neue', Helvetica, sans-serif`
- Моно (методы, URL, JSON, id, шорткаты, тайминги): `ui-monospace, 'SF Mono', Menlo, monospace`

## Цвет

**Поверхности**
- `#ffffff` — контент, карточки, панели
- `#f5f5f7` — холст приложения (за окном ответа)
- `#ececef` — хром: тайтлбар, рейл, статус-бар
- `#f7f7f9` — альтернативная панель списка
- `#f2f2f7` — поля ввода, командная строка

**Текст**
- `#1d1d1f` — основной
- `#6e6e73` — вторичный
- `#86868b` — третичный / мета
- `#a1a1a6` — самый тихий (копирайт)

**Акцент и семантика**
- `#007aff` — акцент (ссылки, активные состояния, primary-кнопка)
- `#34c759` / текст `#1e8e3e` — успех, 2xx
- `#ff9500` / текст `#b26a00` — предупреждение, 3xx
- `#ff3b30` / текст `#d1372c` — ошибка, 4xx/5xx, деструктивные действия
- `#af52de` — инспектор / дополнительный акцент

**Границы**
- `rgba(0,0,0,0.1)` — стандартная граница панелей
- `rgba(0,0,0,0.06)` — граница строки списка/таблицы
- `rgba(0,0,0,0.16)` — граница инпута/кнопки-аутлайн

## Соответствие reka-ui

Проект собирается на **reka-ui** — каждый непростой компонент спецификации маппится на его примитив:

| Компонент дизайна | Примитив reka-ui |
|---|---|
| Поповер «Параметры», «Заголовки», «Auth», «Тело» | `Popover` |
| Дропдаун метода, окружения, языка | `DropdownMenu` или `Select` |
| Контекстное меню строки дерева | `ContextMenu` |
| Диалог подтверждения удаления | `AlertDialog` |
| Модальное «Настройки коллекции» | `Dialog` |
| Тултип | `Tooltip` |
| Тост «Скопировано» | `Toast` |
| Чекбокс (флаги, «Отправлять с запросом») | `Checkbox` |
| Радио (JSON/Raw) | `RadioGroup` |
| Тумблер (настройки) | `Switch` |
| Сегментированный контрол (тема, плотность, масштаб) | `ToggleGroup` |

## Материал «стекло» (новое) — промпт для реализации

Тайтлбар, рейл источников, статус-бар и все поповеры/дропдауны/диалоги теперь — полупрозрачный материал с блюром, а не плоская заливка. Ниже — готовый промпт: можно скопировать в задачу для кодогенерации (Cursor/Copilot/агент), чтобы реализовать то же поведение в реальном приложении на reka-ui.

```
Задача: заменить плоские заливки хром-поверхностей и оверлеев приложения на
материал «стекло» (frosted glass), без изменения структуры/layout компонентов.

Что относится к материалу (применить):
- Тайтлбар окна (высота 52px)
- Рейл источников слева (76px)
- Статус-бар / хлебные крошки снизу (28–34px)
- Поповеры (Параметры, Заголовки, Auth, Тело запроса), дропдауны (метод,
  окружение, коллекции), диалоги (сохранение, удаление), палитра
  глобального поиска (⌘K)

Что НЕ трогать (остаётся непрозрачным #fff):
- Панели контента: сайдбар истории/коллекций, тело запроса/ответа, таблицы,
  формы — там ничего не блюрить, иначе текст под поповером просвечивает и
  накладывается на текст поповера (реальная проблема читаемости, проверено).

⚠️ Исправление после прогона на Windows: старая версия ниже (background:
rgba(255,255,255,0.42) + inset-хайлайт rgba(255,255,255,0.9)) даёт два реальных
дефекта — (1) в тёмной теме тот же rgba(255,255,255,x) токен просто высветляет
хром до серого, тёмная тема не выглядит тёмной; (2) яркий inset-хайлайт поверх
непрозрачного контента снизу создаёт резкую светлую линию-шов на стыке —
это и есть «резкая граница», а не мягкое стекло. Ниже — исправленные токены:
раздельные light/dark, без inset-хайлайта, мягче hairline-граница.

CSS для хром-поверхностей (тайтлбар/рейл/статус-бар):

Светлая тема:
  background: rgba(255,255,255,0.64);
  backdrop-filter: blur(20px) saturate(160%);
  -webkit-backdrop-filter: blur(20px) saturate(160%);
  border-bottom/right/top: 1px solid rgba(0,0,0,0.05); /* было 0.08 — мягче */
  без box-shadow / без inset-хайлайта.

Тёмная тема — ключевое: тонировать в СТОРОНУ ЧЁРНОГО, не белого, иначе
материал читается как светло-серая накладка на тёмном фоне, а не как тёмное
стекло:
  background: rgba(28,28,30,0.6);
  backdrop-filter: blur(20px) saturate(160%);
  -webkit-backdrop-filter: blur(20px) saturate(160%);
  border-bottom/right/top: 1px solid rgba(255,255,255,0.08);
  без inset-хайлайта.
  Фон окна/подложки в тёмной теме: #1c1c1e (не #17171a — разница хром/подложка
  должна быть заметна, иначе стекло снова «не видно»); панели контента
  (сайдбар истории, тело запроса): #232326; текст первичный #f2f2f3,
  вторичный rgba(255,255,255,0.55).

CSS для поповеров/диалогов/палитры (сидят НАД контентом):

Светлая тема:
  background: rgba(255,255,255,0.8);
  backdrop-filter: blur(26–28px) saturate(180%);
  -webkit-backdrop-filter: blur(26–28px) saturate(180%);
  border: 1px solid rgba(0,0,0,0.06–0.07);
  box-shadow: только внешняя тень поповера, без inset-хайлайта.

Тёмная тема:
  background: rgba(40,40,44,0.82);
  backdrop-filter: blur(26–28px) saturate(180%);
  border: 1px solid rgba(255,255,255,0.1);
  box-shadow: только внешняя тень.

Окна-диалоги с собственным хромом (например, менеджер окружений) — весь
диалог получает акриловый материал, а не только его шапка: заливка
rgba(246,246,248,0.72) + blur(30px) saturate(180%) на всём диалоге, шапка и
боковая колонка внутри — на 0.3/0.32 непрозрачнее того же оттенка (не #fff и
не сплошной #f7f7f9), чтобы диалог выглядел одним акриловым листом, а не
стеклянной полоской над обычной белой карточкой.

Правила:
1. Никаких linear-gradient/radial-gradient в заливке материала.
2. Никакого inset-хайлайта (rgba(255,255,255,0.85–0.9)) — на стыке с
   непрозрачным контентом он читается как жёсткий белый шов, а не как
   мягкий переход. Разделение поверхностей — только hairline-граница низкой
   непрозрачности (0.05–0.08), при необходимости — едва заметная внешняя
   тень (0 1px 3px rgba(0,0,0,0.06)), не inset.
3. saturate() обязателен (160–180%) — 220% на реальном контенте перенасыщает
   цвет позади и подчёркивает границу вместо того, чтобы её смягчать.
4. light/dark — это ДВА РАЗНЫХ набора токенов, никогда один и тот же
   rgba(255,255,255,x) на обе темы: light тонирует к белому, dark — к
   тёмно-серому/чёрному (rgba(20–40,20–40,22–44,x)). Меняется не только тема
   текста, но и цвет самой заливки материала.
5. Кроссплатформенность: чистый CSS (background + backdrop-filter), рендерится
   одинаково в Chromium/WebView на macOS, Windows и Linux.
6. Компоненты reka-ui: применять background/backdrop-filter как часть
   `class`/`style` на корневом элементе `Popover.Content`, `DropdownMenu.Content`,
   `Dialog.Content`, `AlertDialog.Content` — сам примитив не меняется, меняется
   только его тема/токен фона (через CSS-переменную, переключаемую классом
   `.dark` на `<html>`, а не хардкодом).
```
