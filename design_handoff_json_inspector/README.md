# Handoff: редизайн JSON Inspector — зоны экрана, режим «Запрос», режим «Браузер»

## Что это

Пакет для реализации редизайна десктопного приложения **JSON Inspector** (Go + Wails v2 + Vue 3 + TypeScript, репозиторий `Jurager/json-inspector`, ветка `main`).

Цель редизайна: убрать дублирование запроса в шапке ответа, перестать сдвигать ответ раскрывающимися панелями, свести интерфейс к семи зонам с одной ответственностью у каждой и задать правило, куда встаёт каждая новая функция.

## О файлах в этом пакете

`JSON Inspector - Зоны и редизайн.dc.html` — **дизайн-референс, сделанный в HTML**. Это прототип: он показывает внешний вид, плотность, порядок элементов и поведение. Это **не продакшн-код и не исходник для копирования**. Задача — воспроизвести эти экраны в существующей среде приложения: Vue 3 SFC + Tailwind v4 через `@apply` + CSS-переменные из `frontend/src/style.css`, теми же компонентами и паттернами, что уже есть в проекте.

Файл открывается в браузере. Внутри три блока: схема зон, прототип режима «Запрос», прототип режима «Браузер» (рабочее и пустое состояние).

## Точность

**High-fidelity.** Цвета, типографика и отступы взяты из текущего `frontend/src/style.css` — новых токенов не вводится. Значения ниже указаны в тех же переменных, что уже в проекте; там, где в прототипе стоит hex, это развёрнутое значение существующей переменной. Иконки в прототипе — из набора `Icon.vue` (lucide, `stroke-width: 1.5`).

## Семь зон экрана

Правило: у каждой зоны одна ответственность, и для каждой новой функции заранее известен адрес.

| № | Зона | Отвечает за | Куда кладём новое |
| --- | --- | --- | --- |
| 1 | Окно (титлбар) | имя приложения, активное окружение, глобальный поиск ⌘K | окружения, переменные, шаринг, аккаунт |
| 2 | Рейл | источники запросов: «Запрос», «Браузер», «Коллекции» | новый **источник** запросов (WebSocket, GraphQL) |
| 3 | Список | содержимое выбранного источника, фильтр снизу | папки, теги, групповое выделение, экспорт |
| 4 | Командная строка / полоса источника | фиксированная высота; метод, URL, чипы, «Отправить» | новая настройка **запроса** — новый чип, не новая панель |
| 5 | Зона ответа | единственная прокручиваемая область; вкладки — способы посмотреть один и тот же ответ | новый **взгляд** на ответ — вкладка |
| 6 | Инспектор (правая колонка, скрыт по умолчанию) | выбранный узел, сравнение ответов | диффы, валидация по схеме, свойства узла |
| 7 | Статус-бар (на всю ширину окна) | фоновые состояния, не требующие реакции | связь с расширением, обновление, счётчики |

Ключевые запреты, которые редизайн вводит:
- ничто не двигает зону ответа вниз — настройки запроса открываются поповером **поверх**;
- URL показан на экране **один раз**;
- ряд вкладок **один**, и он принадлежит ответу;
- состояние перехвата живёт **только** в статус-баре, и статус-бар тянется на всю ширину окна (под рейлом и списком).

## Экран 1 — режим «Запрос»

Порядок сверху вниз: титлбар → (рейл | список | колонка контента) → статус-бар.

### 1. Титлбар

- macOS: нативный, заголовок по центру; Windows/Linux — как сейчас, `.titlebar-custom` со своими кнопками.
- Справа две кнопки высотой 26px, радиус 7px, `border: 1px solid var(--border-strong)`, фон `--bg-panel`:
  - **окружение**: точка 7px `--green` + текст «Local · dev» + `chevron-down` 11px цвета `--text-tertiary`;
  - **поиск**: текст «Поиск» + `⌘K` моно 10.5px цвета `--text-tertiary`.

### 2. Рейл (72px, фон `--bg-sidebar`)

Без изменений по структуре: кнопка меню 36×36 (иконка `menu` 18px), разделитель `--border`, затем тайлы во всю ширину, `padding: 9px 0 7px`, радиус 9px, иконка 18px над подписью 10px/600. Активный тайл — `--accent-soft` + `--accent`. Порядок: **Запрос** (`arrow-up-right`), **Браузер** (`record`, бейдж непрочитанных 16px `--red` в правом верхнем углу), **Коллекции** (иконка папки, новый пункт). Внизу — кнопка настроек 36×36 (`settings-2`).

### 3. Список (288px, фон `--bg-panel`, `border-right: 1px solid var(--border)`)

- Шапка 40px: подпись «История» 12px/600 `--text-secondary` слева, текстовая кнопка «Очистить» справа (без рамки, hover `--bg-hover`).
- Группа-разделитель даты: моно 10px, uppercase, `letter-spacing: .08em`, цвет `--text-tertiary`, `padding: 6px 14px 4px`.
- **Строка списка становится однострочной** (сейчас двухстрочная). Высота ~30px, `margin: 0 6px`, `padding: 7px 10px`, радиус 7px, hover `--bg-hover`, активная `--accent-soft`. Колонки слева направо, `gap: 8px`:
  1. метод — моно 10.5px/600, `min-width: 48px` (не фиксированная ширина: должны влезать `DELETE` и `OPTIONS`), цвет `--accent` для активной строки, `--text-secondary` для остальных;
  2. статус — бейдж `padding: 1px 6px`, радиус 4px, 10px/600, `tabular-nums`: 2xx `--green-soft`/#1e8e3e, 3xx `--orange-soft`/#b26a00, 4xx–5xx `--red-soft`/#d1372c;
  3. путь — моно 11.5px, `flex: 1; min-width: 0`, `text-overflow: ellipsis`. Показывается **path + query**, без схемы и хоста (хост уходит в подсказку `title`);
  4. время — 10.5px `--text-tertiary`, `tabular-nums`.
  Порядок колонок одинаковый для истории и для перехваченных запросов.
- **Фильтр остаётся внизу** (как сейчас в `HistoryPanel`): док на `position: absolute; left/right/bottom: 0`, над ним градиентный smoothstep-заплыв высотой 26px, сам инпут — высота 28px, радиус 7px, фон `rgba(0,0,0,.045)`, `backdrop-filter: blur(12px)`, **без рамки**, внутри иконка `search` 12px и плейсхолдер «Фильтр по ссылке, методу, статусу…». Список получает нижний отступ 46px, чтобы последняя строка не пряталась под доком.

### 4. Командная строка (56px, фон `--bg-panel`, `border-bottom: 1px solid var(--border)`)

Одна строка, высота фиксирована — ничто в ней не раскрывается вниз.

- Поле URL: `flex: 1`, высота 32px, радиус 8px, фон `--bg-inset`, `border: 1px solid var(--border)`, `padding: 0 6px 0 5px`. Focus — `border-color: var(--accent)` + `box-shadow: 0 0 0 3px var(--accent-soft)` (как `.input:focus`).
- **Метод — чип внутри поля**, слева: высота 22px, `padding: 0 7px`, радиус 6px, без рамки, моно 11px/600, фон и цвет по семантике метода (GET — `rgba(52,199,89,.16)` / #1e8e3e; POST — `--accent-soft` / `--accent`; PUT/PATCH — `--orange-soft` / #b26a00; DELETE — `--red-soft` / #d1372c), справа `chevron-down` 10px. Клик открывает меню методов (`.menu`).
- Текст URL — моно 12.5px `--text`, `flex: 1; min-width: 0`, ellipsis.
- **Чипы конфигурации** прижаты к правому краю поля, высота 22px, `padding: 0 8px`, радиус 6px, фон `--bg-panel`, `border: 1px solid var(--border)`, 11px `--text-secondary`; hover — `border-color: var(--border-strong)`, цвет `--text`:
  - «Параметры» + счётчик (моно 11px/600 `--accent`);
  - «Заголовки» + счётчик;
  - «Auth»;
  - «Тело» — пунктирная рамка `1px dashed rgba(0,0,0,.18)`, прозрачный фон, цвет `--text-tertiary`, когда тела нет; сплошная и `--text`, когда есть.
- Кнопка «Отправить»: высота 32px, `padding: 0 14px`, радиус 8px, `--accent` фон, белый текст 12.5px/500, внутри кэпс `⌘↵` на `rgba(255,255,255,.22)`. В состоянии загрузки — «Отмена» с иконкой `xmark` (как сейчас).

### 5. Поповеры чипов (вместо раскрывающихся панелей)

`position: absolute`, под чипом, ширина 460px (Auth — 380px), фон `--bg-panel`, `border: 1px solid var(--border)`, радиус 10px, тень `0 12px 32px rgba(0,0,0,.16)`, `padding: 10px`, `z-index` выше шапки ответа.

- Заголовок: 12px/600 + кнопка закрытия `xmark`.
- Строка параметра/заголовка — грид `20px 150px 1fr 22px`, `gap: 6px`, `padding: 3px 4px`: чекбокс 13px (включён — `--accent` с галочкой; выключен — рамка `--border-strong`), имя моно 11.5px `--text`, значение моно 11.5px с подсветкой типа (`--tok-str` для строк, `--tok-num` для чисел), кнопка удаления `xmark` (hover — `--red`).
- Выключенная строка — `opacity: .55`, и она не уходит в запрос.
- Подвал: текстовая кнопка «+ Параметр» / «+ Заголовок» цвета `--accent` слева, подсказка 11px `--text-tertiary` справа, `border-top: 1px solid var(--border)`.
- Auth: сегментированный контрол на `--bg-inset` (Нет / Bearer / Basic / OAuth 2), активный сегмент — `--bg-panel` + тень.
- Закрытие: клик вне (тот же паттерн `onDocClick`, что у меню копирования), Esc, повторный клик по чипу.

### 6. Шапка ответа (48px, `.resp-bar`)

Структура сохраняется, **но URL из неё убирается в режиме «Запрос»** — он уже стоит в командной строке. Остаётся: статус-бейдж («200 OK»), время, размер, content-type, разделители 1×12px `--border`. Справа действия высотой 24px: «Сравнить», «Копировать ▾», «Инспектор ⌥I».

В режиме «Браузер» — наоборот: командной строки нет, и шапка берёт URL на себя (см. экран 2).

### 7. Вкладки ответа (44px, `.tabs`)

Порядок: **Тело · Карта · Raw · Заголовки · Cookies · Тайминги · Тесты · Запрос**. Активная — `--accent`, 500, нижняя граница 2px `--accent`; остальные `--text-secondary`. Карта — только для JSON:API-документа (как сейчас). Cookies, Тайминги, Тесты — новые вкладки, их можно добавлять по одной; порядок остаётся.

Под вкладками — существующий `.toolbar`: пагинация (`chevrons-left`, `chevron-left`, `chevron-right`, `chevrons-right`) слева, спейсер, «Копировать» и «Поиск ⌘F» справа; поиск разворачивается в этой же строке.

### 8. Тело ответа

Структура `JsonApiTree` + `ResourceNode` сохраняется: заголовки разделов `data` / `included (N)` моно 10px uppercase `--text-tertiary`; карточка ресурса — `--bg-panel`, `border: 1px solid var(--border)`, радиус 9px, `margin: 6px 16px`; шапка карточки — `<button>` с кареткой `chevron-right` 10–11px (повёрнутой на 90° в раскрытом виде), бейджем типа (`--purple` на `color-mix(--purple 14%)`), id моно `--text-secondary` и подписью 500. Внутри — разделы `attributes` и `relationships`, строки атрибутов моно 11.5px с колонкой ключа `min-width: 120px`, значения кликабельны для копирования (`.copied` — `--accent-soft`). Чипы связей: в документе — `--accent` с рамкой `rgba(0,122,255,.45)`; загружаемые по `links.related` — `--orange` пунктиром; отсутствующие — `--text-tertiary` без курсора.

**Изменение:** `included` получает сводку по типам в заголовке раздела (чипы «entityAttributes 61», «productPrice 12», «ещё N») и раскрывается группами по типу вместо плоского списка. При 94 ресурсах плоский список нечитаем.

### 9. Инспектор (300px, скрыт по умолчанию)

`border-left: 1px solid var(--border)`, фон `--bg-panel`. Шапка 38px с подписью «Инспектор узла» и `xmark`. Блоки: «Путь» (моно 11.5px, `word-break: break-all`), «Связь», «Схема» (точка-индикатор + текст), «Действия» (кнопки «Открыть links.related», «Скопировать путь»). Открывается кнопкой в шапке ответа и по ⌥I; состояние ширины и видимости запоминается.

### 10. Статус-бар (28px, НОВОЕ)

Дочерний элемент корня приложения, **после** строки «рейл + контент», на всю ширину окна. Фон `--bg-sidebar`, `border-top: 1px solid var(--border)`, `padding: 0 14px`, текст 11.5px `--text-secondary`.

- Режим «Запрос»: слева окружение («Local · dev»), справа сводка документа («JSON:API 1.0 · 8 ресурсов · 2 связи не загружены»).
- Режим «Браузер»: слева точка состояния + «Запись · Chrome · 2 вкладки под перехватом», справа та же сводка.
- Здесь же — предложение обновиться вместо модального окна.

## Экран 2 — режим «Браузер»

Отличия от режима «Запрос»:

1. **Командной строки нет.** Запросы уже выполнены, отправлять нечего. Вместо неё — **полоса источника** 38px, фон `--bg-inset`, `border-bottom: 1px solid var(--border)`: слева «Источник: вкладка «…»» 11.5px `--text-secondary`, справа подпись 11.5px `--text-tertiary` «Только чтение — запросы уже выполнены» и кнопка 24px «Приостановить перехват». **Состояния записи в этой полосе нет** — оно только в статус-баре.
2. **Шапка ответа берёт URL на себя** — это единственное место, где он показан. Состав: кнопка «назад» 24×24 (`chevron-left`, только если есть предыдущий в том же источнике — логика `hasPrev` сохраняется), чип метода, бейдж статуса, `хост + путь` моно 12.5px, чип «Параметры N», спейсер, «742 мс · 35,1 КБ» `--text-tertiary`.
   Полная строка URL не выводится: длинный `include=a.b,c.d,…` сворачивается в чип со счётчиком, полное значение доступно в поповере параметров и через «Копировать».
3. **Тулбар под вкладками** — существующий `.toolbar`: пагинация слева, справа «Открыть в „Запросе“» (цвет `--accent`, переносит перехваченный запрос в редактируемый вид режима «Запрос»), «Копировать ▾», «Поиск ⌘F».
4. **Список сгруппирован по вкладкам браузера** — как уже реализовано в `HistoryPanel` для источника `browser`: шапка группы с кареткой, favicon 18×18 (при ошибке — цветной аватар с первой буквой), заголовок вкладки, счётчик, `xmark` для очистки группы. У активно записываемой группы — метка «запись»: точка 6px `--red` + текст 10.5px `--red`. Строки внутри группы — с отступом 14px слева, форма строки та же, что в истории.
5. **Пустое состояние — одно, а не два.** Сейчас экран говорит дважды: «Пока пусто» в списке и «Нет выбранного запроса» в центре. Пока перехвата нет, выбирать нечего: список пуст без текста, а в центре — один онбординг шириной 560px:
   - заголовок 17px/600 «Подключите расширение, чтобы видеть запросы браузера»;
   - подзаголовок 13px `--text-secondary`;
   - три пронумерованных шага (кружок 18px `--bg-inset`, текст 13px): установить расширение из `extension/` в режиме разработчика; включить «Перехватывать эту вкладку» в попапе; вернуться — вкладка появится в списке как группа;
   - кнопка `--accent` «Открыть инструкцию» и строка состояния: точка `--orange` + «Расширение не найдено · порт слушает».
   Статус-бар в этом состоянии показывает «Перехват не запущен · ожидание расширения».

## Взаимодействия и состояния

- Чипы командной строки: клик — открыть/закрыть поповер; открытым может быть только один; закрытие по Esc и клику вне. Раскрытие **не меняет высоту** командной строки и не сдвигает ответ.
- Счётчик на чипе = число включённых параметров/заголовков. Выключенные строки в запрос не уходят.
- ⌘↵ — отправить, ⌘F — поиск в активной вкладке, ⌘K — глобальный поиск, ⌥I — инспектор, Esc — закрыть поповер/поиск.
- Переключение вкладки ответа сбрасывается на «Тело» при смене записи (как сейчас `watch(record.id)`).
- «Открыть в „Запросе“» копирует метод, URL, заголовки и тело перехваченного запроса в командную строку и переключает рейл на «Запрос».
- Hover: кнопки — `--bg-hover`; строки списка — `--bg-hover`; чипы — `border-color: var(--border-strong)`; карточка ресурса — `border-color: rgba(0,0,0,.22)`.
