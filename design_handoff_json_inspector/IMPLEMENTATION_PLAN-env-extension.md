# План реализации: окружения и расширение

Пошаговый план для `Jurager/json-inspector` (ветка `main`). Продолжение первого пакета (`IMPLEMENTATION_PLAN.md`, шаги 0–9). Каждый шаг самодостаточен: после него приложение собирается и работает. Спецификация — `README-env-extension.md`, дизайн-референс — блоки **05 · Окружения** и **04 · Расширение** в `JSON Inspector - Зоны и редизайн.dc.html`.

Порядок: сначала ядро подстановки (A1–A2), потом интерфейс окружений (A3–A6), потом секреты и импорт (A7–A8), потом расширение (B1–B4). Части A и B независимы — B можно делать параллельно, но после A, чтобы не смешивать в одной ветке.

---

## Шаг A1 — ядро подстановки

**Файлы:** `frontend/src/lib/vars.ts` (новый), тесты рядом, если в проекте есть vitest.

1. `parseTokens(text): { start, end, name, raw }[]` — находит `{{name}}` и `{{ name }}`; `\{{` считается экранированием и токеном не является.
2. `substitute(text, resolve)` — заменяет токены значениями; неизвестные оставляет как есть.
3. `missing(text, resolve): string[]` — уникальные имена, для которых `resolve` вернул `null`.
4. Имя переменной: `[A-Za-z_][A-Za-z0-9_]*`. Всё остальное внутри скобок токеном не считается.

**Приёмка:** `{{baseUrl}}/v1/{{ tenant }}` даёт две подстановки; `\{{baseUrl}}` остаётся текстом; вложенные скобки не ломают разбор.

## Шаг A2 — стор окружений

**Файлы:** `frontend/src/stores/environments.ts` (новый), `frontend/src/main.ts` (регистрация, если нужна).

1. Состояние, геттеры и экшены — по разделу «Хранение и состояние» спецификации.
2. `resolve(name)` идёт по цепочке: запрос → активное окружение → глобальные; выключенные переменные пропускаются.
3. Персист в `localStorage` под `ji-env-v1` — тем же способом, что `ji-history-v1`. Секреты в сериализацию не попадают.
4. Значения по умолчанию на первый запуск: одно окружение «Local · dev» с `baseUrl = http://localhost:8000`, без секретов. Prod не создаём сами.

**Приёмка:** перезапуск приложения сохраняет окружения, переменные и выбор активного; `resolve` отдаёт источник (`env` / `global`).

## Шаг A3 — меню окружения в титлбаре

**Файлы:** `frontend/src/components/EnvironmentMenu.vue` (новый), `frontend/src/App.vue`, `frontend/src/style.css`.

1. Чип в титлбаре из первого пакета начинает открывать меню: 280px, радиус 11px, `--shadow`, `padding: 6px`.
2. Состав по спецификации: список окружений с галочкой и счётчиком, бейдж «только чтение», пункт «Без окружения», разделитель, «Редактировать переменные… ⌘E».

**Приёмка:** смена окружения из меню мгновенно меняет подставленные значения в подсказках токенов; меню закрывается всеми тремя способами; ничего не появилось в рейле.

## Шаг A4 — токены в полях

**Файлы:** `frontend/src/components/VarToken.vue` (новый), `RequestBuilder.vue`, `RequestChipPopover.vue`, `style.css`.

1. Поле URL рендерит текст сегментами: обычный текст и `VarToken`. Правка остаётся текстовой — подсветка накладывается на отображаемый слой, ввод не ломаем (если это дорого, начните с подсветки в неактивном состоянии поля и покажите результат до перехода к тултипам).
2. Тултип по наведению: значение (моно 11.5px) + источник и подсказка про ⌥клик. Для секрета — «значение скрыто · секрет».
3. ⌥клик по токену — `environments.openSheet({ envId, varName })`.
4. Те же токены — в значениях строк параметров и заголовков в поповерах.

**Приёмка:** курсор по токену показывает значение и источник; секрет не раскрывается; ввод и выделение текста в поле URL работают как раньше.

## Шаг A5 — состояние «переменная не найдена»

**Файлы:** `RequestBuilder.vue`, `StatusBar.vue`, `stores/requests.ts`.

1. Неизвестный токен: красная подсветка с волнистым подчёркиванием, рамка поля `rgba(255,59,48,.45)`.
2. Под полем — строка ошибки на `rgba(255,59,48,.07)` с кнопкой «Создать»: создаёт переменную в активном окружении и открывает лист с фокусом на ней.
3. Пока `missing.length > 0`, «Отправить» и `⌘↵` заблокированы (кнопка `disabled`, подсказка в `title`).
4. Статус-бар слева показывает «N переменных не найдено» цветом #d1372c.

**Приёмка:** отправка невозможна при неизвестной переменной; после создания переменной поле и кнопка возвращаются в норму без перезагрузки.

## Шаг A6 — лист редактора (⌘E)

**Файлы:** `frontend/src/components/EnvironmentsSheet.vue` (новый), `App.vue`, `Icon.vue`, `style.css`.

1. Модальный лист 1040×(46+548), радиус 12px, тень; фон-затемнение `rgba(0,0,0,.25)`. Esc и «Готово» закрывают, фокус возвращается в поле URL. Список переменных скроллится (`flex: 1; min-height: 0; overflow-y: auto`), подвал прибит (`flex: none`).
2. Левая колонка 232px: окружения, «Глобальные», подвал с `+` / `−` и «Импорт .env».
3. Правая колонка: тулбар только с фильтром (кнопки «Показать секреты» нет), таблица `200px | 1fr | 96px | 34px`, строки 38px, правка по месту (Enter / Esc / Tab), строка «+ Новая переменная», подвал про связку ключей.
4. Секрет раскрывается построчно: кнопка-глаз 20×20 в ячейке значения (`eye` / `eye-off`), состояние в `revealed`, сброс при закрытии листа.
5. Валидация: пустое имя и дубликат в пределах окружения подсвечиваются, сохранение блокируется.
6. Read-only окружение: ячейки не редактируются, в тулбаре кнопка «Разблокировать» (`unlocked` живёт до закрытия листа).
7. Удаление окружения — подтверждение, если на его переменные ссылается сохранённый запрос.
8. Новые иконки в `ICONS`: `Lock`, `List`, `Plus`, `Minus`, `Eye`, `EyeOff`, `CornerDownRight`, `Pencil`.

**Приёмка:** переменная создаётся, переименовывается и удаляется без перезагрузки; дубликат имени не сохраняется; секрет раскрывается только в своей строке; Prod не правится без разблокировки; подвал листа виден целиком при любом числе строк; лист не двигает окно под собой.

## Шаг A6б — имя окружения и глобальные в таблице

**Файлы:** `EnvironmentsSheet.vue`, `stores/environments.ts`.

1. **Создание и переименование прямо в строке списка** (паттерн Finder): `+` создаёт строку сразу в режиме ввода с выделенным именем «Новое окружение»; двойной клик или Enter на выделенной строке переименовывает. Enter и клик вне сохраняют, Esc отменяет, пустое имя и дубликат не сохраняются (красная рамка, фокус остаётся).
2. **Геометрия инпута повторяет строку:** строка 30px, инпут 26px, `box-sizing: border-box`, текст выровнен по той же вертикали и той же левой границе, что имена соседних строк. Проверь по прототипу: переход в режим ввода не сдвигает ни строку, ни соседние.
3. **Группа «Наследуется из глобальных»** под собственными переменными окружения: заголовок 30px со счётчиком и пояснением, строки с иконкой наследования, серым текстом и бейджем «глобальная». Раздел «Глобальные» слева остаётся местом их редактирования и удаления.
4. **Переопределение без отдельной команды:** одноимённая переменная в обычном списке выигрывает, а строка глобальной ниже зачёркивается, блекнет и получает серый бейдж «перекрыта» + `title` «Перекрыта переменной окружения». Удаление своей строки возвращает глобальную в строй без подтверждений.
5. Геттер `rowsFor(envId)` считает `own` и `inherited` с флагом `overridden` — компонент не сравнивает имена сам.

**Приёмка:** новое окружение создаётся и называется за один жест; переименование сразу видно в чипе титлбара и статус-баре; глобальные видны в каждом окружении; заведённая одноимённая переменная зачёркивает глобальную и побеждает в подстановке.

## Шаг A7 — секреты

**Файлы:** `internal/secrets/keyring.go` (новый), `app.go`, `frontend/src/stores/environments.ts`, `frontend/src/lib/export.ts`.

1. Go-сторона: `SecretSet/SecretGet/SecretDelete/SecretList` через связку ключей, сервис `json-inspector`, аккаунт `env:<envId>:<varName>`. Экспортировать методы в фронт через Wails.
2. Стор держит секреты только в памяти; при старте подтягивает их через `SecretList` активного окружения.
3. Связка ключей недоступна — не падаем: работаем в памяти и пишем в подвале листа «Связка ключей недоступна — секреты не сохранятся после выхода».
4. `export.ts`: секреты не выгружаются; в «Копировать как cURL» по умолчанию значения подставлены, в меню — вариант «оставить токены».

**Приёмка:** секрет переживает перезапуск приложения; в `localStorage` его значения нет; экспорт запроса не содержит секретов; на системе без связки ключей приложение работает и честно об этом пишет.

## Шаг A8 — импорт .env

**Файлы:** `EnvironmentsSheet.vue`, `stores/environments.ts`.

1. Разбор: `KEY=value`, `#` — комментарий, `export ` игнорируется, кавычки снимаются, пустые строки пропускаются.
2. Диалог подтверждения: список строк с чекбоксом «секрет» (предзаполнен для имён с `TOKEN`, `SECRET`, `PASSWORD`, `KEY`, `AUTH`), для конфликтов — выбор «заменить» / «пропустить».
3. Импорт идёт в выбранное слева окружение, не в глобальные.

**Приёмка:** файл на 20 строк импортируется одним подтверждением; существующие значения не перезаписываются молча.

## Шаг B1 — состояние в `background.js`

**Файлы:** `extension/background.js`, `extension/manifest.json` (если понадобится разрешение `tabs`).

1. `getState` начинает отдавать `currentTab` (`tabId`, `title`, `url`, `favIconUrl`, `count`, `lastAt`, `capturing`), `bufferedCount` и `settings`.
2. Новые сообщения: `setSetting({ key, value })`, `openApp({ tabId })`.
3. `settings.xhrOnly` — фильтр по типу ресурса при перехвате; `rememberTabs` — восстановление перехвата по origin при старте браузера; `clearOnExit` — не сохранять тела.
4. `bufferedCount` растёт, пока приложение не отвечает, и обнуляется после успешной отдачи.

**Приёмка:** попап получает имя и хост активной вкладки без дополнительных запросов; выключенный `xhrOnly` возвращает прежнее поведение; настройки переживают перезапуск браузера.

## Шаг B3 — логика попапа

**Файлы:** `extension/popup/popup.js`.

1. Рендер из нового `getState`: шапка, карточка текущей вкладки, список остальных, кнопка.
2. Счётчик и строки списка кликабельны: `openApp({ tabId })`.
3. «Приложение не запущено»: карточка-предупреждение с кнопкой «Запустить приложение», карточка вкладки приглушена, строка про буфер.
4. Экран настроек: порт (как сейчас `setPort`), три тумблера через `setSetting`, версия из `chrome.runtime.getManifest()`.
5. Опрос состояния — оставить существующий `setInterval` 2.5 с; при открытом экране настроек не перерисовывать поля, в которых стоит фокус.

**Приёмка:** тумблер текущей вкладки включает и выключает перехват именно активной вкладки; клик по счётчику открывает приложение на ней; правка порта не сбрасывается опросом.

## Шаг B4 — глубокая ссылка на вкладку

**Файлы:** `internal/bridge/server.go`, `frontend/src/stores/requests.ts`, `frontend/src/components/HistoryPanel.vue`.

1. `json-inspector://open?tab=<tabId>` открывает приложение, переключает рейл на «Браузер» и разворачивает группу этой вкладки, выбирая последний запрос.
2. Если группы ещё нет — просто режим «Браузер» без ошибок.

**Приёмка:** из попапа попадаешь ровно в нужную группу; повторный клик при уже открытом приложении выводит окно вперёд.

## Что проверить в конце

- Смена окружения не трогает сохранённые запросы, только подстановки.
- Секреты не видны нигде, кроме строки, где явно нажали глаз.
- Глобальная переменная всегда видна в том окружении, где она действует, и честно зачёркнута, когда не действует.
- Отправка блокируется ровно тогда, когда есть ненайденная переменная, и разблокируется сразу после её создания.
- Попап всегда отвечает на вопрос «пишется ли эта вкладка» одним взглядом.
- Приложение и расширение переживают ситуацию «второй стороны нет» без модалок и без потери данных.
