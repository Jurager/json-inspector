# Handoff 3: коллекции

## Что это

Третий пакет для `Jurager/json-inspector`. Продолжает `README.md` (зоны 1–7) и `README-env-extension.md` (переменные, расширение). Закрывает коллекции сохранённых запросов — третий источник в рейле (зона 2), рядом с «Запрос» и «Браузер».

Дизайн-референс: `JSON Inspector - Зоны и редизайн.dc.html`, блок **06 · Коллекции**. Прототип, не исходник — состав, порядок, плотность и значения переносятся в Vue 3 SFC + Tailwind v4 (`@apply`) + переменные `frontend/src/style.css`, новых цветовых токенов не вводится.

## Модель

```ts
interface CollectionRequest {
  id: string; name: string; method: string; url: string
  params: { name: string; value: string; enabled: boolean }[]
  headers: { name: string; value: string; enabled: boolean }[]
  auth: { type: 'none' | 'inherit' | 'bearer' | 'basic' | 'apikey' | 'oauth2' | 'jwt' | 'digest' | 'aws'; fields: Record<string, string> }
  body: string; description?: string
}
interface CollectionFolder { id: string; name: string; items: (CollectionFolder | CollectionRequest)[] }
interface Collection {
  id: string; name: string; description?: string
  items: (CollectionFolder | CollectionRequest)[]
  lastRun?: { at: string; passed: number; failed: number; durationMs: number; results: RunResult[] }
}
interface RunResult { requestId: string; status: number | null; ok: boolean; durationMs: number; error?: string }
```

## Где это в интерфейсе

### 1. Рейл (зона 2)

Пункт «Коллекции» уже зарезервирован в первом пакете, иконка `folder`. Активный — `--accent-soft` / `--accent`, как «Запрос» и «Браузер».

### 2. Список — дерево (зона 3)

- Шапка 40px: подпись «Коллекции» слева, кнопка «+» справа (новая коллекция), 24×24, вместо «Очистить».
- Строки дерева, отступ по уровню (0 / 24px / 40px): коллекция — жирнее, со счётчиком запросов; папка — обычным весом, со своим счётчиком; запрос — метод моно 10px/600 `min-width: 40px` (та же ширина, что в истории, чтобы `DELETE` не обрезался) + имя запроса (не URL — у сохранённого запроса собственное имя).
- Разворот — chevron слева, поворот 90° при раскрытии, тот же приём, что у групп в режиме «Браузер» и у карточек ресурса.
- Выбранная строка — `--accent-soft` фон, текст `--accent`.
- Правый клик — контекстное меню (`.menu`, тот же паттерн everywhere): строки **без иконок**, как в системных macOS-меню — «Переименовать», «Дублировать», «Экспорт запроса», разделитель, «Удалить» (`--red`). На коллекции и папке — дополнительно «Новая папка» и «Новый запрос» сверху списка.
- Фильтр закреплён внизу, тот же паттерн, что в истории: докнутый инпут с градиентным заплывом 26px, placeholder «Поиск по коллекции…»; ищет по имени на любой глубине, совпадение разворачивает родителей.
- **Пустое состояние:** пока коллекций нет вообще, зона списка не рисуется — показывать 288-пиксельную панель с одним «+» смысла нет. Сразу после рейла — зона контента на всю ширину с центрированным онбордингом («+ Новая коллекция» / «Импортировать коллекцию»). Список появляется вместе с первой коллекцией, которая сразу становится выбранной.

### 3. Карточка запроса — без перехода в «Запрос» (зоны 4–8)

Открытие сохранённого запроса **не переключает рейл** и не копирует запрос в черновик режима «Запрос» — редактирование и отправка происходят прямо в «Коллекциях», тем же визуальным языком:

- титлбар не трогаем — остаётся «JSON Inspector», как везде. Путь и статус правки живут в **статус-баре** (зона 7), а не над командной строкой: это фоновая информация, а не то, что нужно для отправки запроса, и зона 7 — её штатное место (тот же принцип, что у состояния расширения в режиме «Браузер»).
- статус-бар слева: хлебные крошки `Коллекция › Папка › Имя запроса` 11.5px `--text-secondary`, последний сегмент — `--text`/600. Справа: индикатор несохранённой правки (точка `--orange` + текст «Не сохранено» + кнопка «Сохранить», 18px, видна только когда есть изменения), разделитель, сводка документа (как в режиме «Запрос»).
- командная строка (зона 4) и зона ответа (зона 5–8) — **та же разметка**, что в режиме «Запрос»: метод-чип, поле URL, чипы Параметры/Заголовки/Auth/Тело, «Отправить», вкладки ответа. Не копия компонента — тот же `RequestBuilder`/`ResponseViewer`, источник данных — элемент коллекции вместо `store.draft`;
- правка URL/параметров/заголовков/тела помечает элемент изменённым (индикатор в статус-баре). «Сохранить» пишет правку обратно в коллекцию; «Отправить» просто выполняет запрос — это разные действия, отправка не сохраняет.

### 4. Коллекция или папка — обзор и прогон (замещает карточку запроса)

Когда в дереве выбрана коллекция или папка (не отдельный запрос), зона контента показывает:

- шапку: имя 20px/600 + счётчик запросов 11.5px `--text-tertiary`, под ней описание 13px `--text-secondary`, время последнего прогона справа во втором ряду;
- ряд действий: «Запустить коллекцию» (`--accent`, иконка `play`), «Импорт» и «Экспорт» (вторичный стиль, иконки `download`/`upload`);
- после прогона — сводка из 4 блоков (запросов / успешно `--green` / ошибок `--red` / общее время), затем построчный результат: иконка (галка `--green` / крест `--red`) + метод + имя + бейдж статуса + длительность — тот же визуальный язык, что у строки истории; строка с ошибкой — лёгкий фон `rgba(255,59,48,.04)`;
- прогон идёт последовательно по всем запросам узла, ошибка одного не останавливает остальные;
- запуск папки (не всей коллекции) прогоняет только её поддерево.

### 5. Сохранение запроса из командной строки режима «Запрос»

В зоне 4 (командная строка режима «Запрос»), рядом с «Отправить» — новая кнопка-закладка 32×32, `border: 1px solid var(--border-strong)`, иконка `bookmark`. Клик открывает поповер 320px:

- заголовок «Сохранить запрос»;
- поле имени, по умолчанию — путь запроса без query или последний сегмент;
- список коллекций/папок для выбора места (не дерево на всю высоту — тот же список, что в зоне 3, свёрнутый до нужной глубины), выбранная строка — `--accent-soft`;
- «Отмена» / «Сохранить» (`--accent`).

Сохранение копирует метод, URL, параметры, заголовки, auth и тело текущего черновика в новый элемент коллекции; черновик в командной строке не меняется.

### 6. Импорт/экспорт

- «Импорт» на уровне коллекции — диалог выбора файла, формат — Postman Collection v2.1 (`info`, `item[]`, `request.url/method/header/body`). Файл без этой структуры — сообщение об ошибке формата, без попытки угадать.
- «Экспорт» — тот же формат, диалог сохранения; экспорт одного запроса (из контекстного меню) — файл с одним `item`.
- Секреты (см. `README-env-extension.md`) в экспорт не попадают — только токены `{{name}}`.

### 7. Создание — прямо в дереве (паттерн Finder, как у окружений)

- «+» в шапке списка создаёт коллекцию сразу строкой в режиме ввода, имя по умолчанию «Новая коллекция» выделено целиком; Enter сохраняет, Esc отменяет, пустое имя и дубликат не сохраняются (красная рамка, фокус остаётся).
- «Новый запрос» из контекстного меню коллекции/папки добавляет строку с методом (чип, по умолчанию GET, кликабелен и меняется сразу же) и именем в режиме ввода; URL и остальное — уже в открытой карточке запроса.
- Геометрия инпута повторяет строку дерева (30px), тот же приём, что у переименования окружений: инпут 26px, `box-sizing: border-box`, текст на той же вертикали, что имя соседних строк.

### 8. Несохранённые изменения при переходе

Кнопку «Сохранить» в статус-баре легко не заметить, поэтому уход с несохранённой правки не проходит тихо. Системный алерт macOS (иконка приложения, заголовок «Сохранить изменения в «Имя запроса»?», подзаголовок, три кнопки: «Не сохранять» слева отдельно, «Отмена» и «Сохранить» справа, «Сохранить» — кольцо фокуса) появляется при: выборе другого узла дерева, переключении рейла на «Запрос»/«Браузер», закрытии окна — везде, где есть `dirty`. «Не сохранять» отбрасывает правку и продолжает переход; «Отмена» остаётся на месте; «Сохранить» пишет и продолжает.

## Взаимодействия

- Клик по запросу в дереве — открывает карточку запроса, рейл остаётся на «Коллекции».
- Клик по коллекции/папке — открывает обзор/прогон.
- Правый клик — контекстное меню; закрытие по Esc, клику вне (`onDocClick`), повторному правому клику.
- Переименование — двойной клик по имени, тот же паттерн Finder, что у окружений.
- Удаление коллекции/папки с более чем одним запросом внутри — подтверждение.
- Drag-and-drop внутри дерева — вне этого пакета; порядок и вложенность меняются только через контекстное меню.

## Приёмка пакета

- Открытие сохранённого запроса не переключает рейл на «Запрос» и не трогает черновик там.
- Правка запроса внутри коллекции помечена индикатором и требует явного «Сохранить»; «Отправить» её не сохраняет.
- Прогон коллекции проходит все запросы, ошибка одного не останавливает остальные; сводка и построчные результаты совпадают.
- Контекстное меню даёт переименовать/дублировать/удалить/экспортировать на любом уровне и создать папку/запрос на коллекции и папке.
- Фильтр находит запрос по имени на любой глубине и разворачивает путь до него.
- Импорт/экспорт совместимы с форматом Postman Collection v2.1; секреты не экспортируются.
