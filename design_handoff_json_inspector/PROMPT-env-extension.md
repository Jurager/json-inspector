Три решения, которые важно не потерять по дороге:
- окружение создаётся и переименовывается прямо в строке списка (паттерн Finder), без отдельного диалога, и инпут обязан вставать в ритм строки, а не распирать её;
- глобальные переменные показываются внутри таблицы каждого окружения отдельной группой; переопределение делается обычной одноимённой переменной, а глобальная строка при этом зачёркивается с пометкой «перекрыта»;
- общей кнопки «Показать секреты» нет — у каждой секретной строки свой глаз рядом со значением.

Правила на всю работу:
- Новых цветов не вводить. В приложении — только переменные из frontend/src/style.css; в попапе — те же значения, что в прототипе, и рабочая тёмная тема через prefers-color-scheme.
- Окружение — свойство окна, а не запроса. Новый раздел в рейле не появляется: вход только через чип в титлбаре и ⌘E.
- Стили в приложении — как в проекте: `<style scoped>` + `@reference "../style.css"` + `@apply`; общие классы — в style.css.
- Иконки — только через Icon.vue (lucide, stroke-width 1.5). Нужна новая — добавь в карту ICONS, не рисуй SVG вручную.
- Переиспользуй существующие утилиты и паттерны: onDocClick для закрытия поповеров, shortcut() из lib/platform.ts, персист рядом с ji-history-v1, copyToClipboard и exportRequest из lib/export.ts.
- Секреты не должны попадать ни в localStorage, ни в экспорт, ни в логи. Если связка ключей недоступна — не падать, а честно сообщить в интерфейсе.
- Ничего не ломай по дороге: после каждого шага приложение должно собираться и работать, расширение — загружаться в Chrome без ошибок в консоли service worker.
- Комментарии в коде — в стиле проекта: объясняют «почему», а не «что».
