Ты работаешь в репозитории json-inspector (Go + Wails v2 + Vue 3 + TypeScript). Первые два этапа редизайна (зоны 1–7; переменные окружения и расширение) уже внедрены. Нужно внедрить третий: коллекции сохранённых запросов.

- `design_handoff_json_inspector/README-collections.md` — спецификация этого этапа: модель, дерево, карточка запроса без перехода, обзор и прогон коллекции, сохранение из командной строки, импорт/экспорт.
- `design_handoff_json_inspector/IMPLEMENTATION_PLAN-collections.md` — шаги D1–D7 с файлами и критериями приёмки.
- `design_handoff_json_inspector/JSON Inspector - Зоны и редизайн.dc.html` — блок «06 · Коллекции». Дизайн-референс, не код для копирования: бери состав, порядок, значения, реализуй средствами проекта (Vue 3 SFC + Tailwind v4 `@apply` + переменные `frontend/src/style.css`).

Затем выполни шаги D1–D7 по порядку.

Решение, которое важно не потерять: открытие сохранённого запроса **не переключает рейл на «Запрос»** и не копирует запрос в черновик там — командная строка и зона ответа переиспользуются на месте, в «Коллекциях», с элементом коллекции как источником данных вместо `store.draft`. Правка запроса и его отправка — разные действия: «Сохранить» пишет правку в коллекцию, «Отправить» просто выполняет запрос.

Правила на всю работу:
- Новых цветов не вводить. Только переменные из `frontend/src/style.css`. Тёмная тема обязана работать.
- Стили — `<style scoped>` + `@reference "../style.css"` + `@apply`; общие классы — в `style.css`.
- Иконки — только через `Icon.vue` (lucide, `stroke-width: 1.5`). Нужна новая — добавь в `ICONS`.
- Переиспользуй `RequestBuilder.vue` и `ResponseViewer.vue` как есть, передавая источник данных пропом — не создавай параллельные компоненты для карточки запроса коллекции.
- Ничего не ломай по дороге: после каждого шага приложение собирается и работает.
- Комментарии в коде — в стиле проекта: объясняют «почему».

Процесс по каждому шагу: назови шаг одной строкой → внеси изменения → `make build` (или `npx vue-tsc --noEmit`) → проверь по списку «Приёмка» → коммит `collections(step D2): краткое описание` → следующий шаг без вопросов, если приёмка прошла.

Останавливайся и спрашивай только если: план расходится с кодом так, что решение неочевидно; шаг требует удалить функциональность, не упомянутую в плане; сборка падает и причина не в твоих правках.

Не делай ничего сверх плана: drag-and-drop в дереве, переменные на уровне коллекции и совместный запуск с CI — не в этом заходе.
